# Deploying for development and testing (free)

Target: a shareable test copy for a handful of testers. **Demo data only.** Free tiers have no backups or uptime
promise, so never load real customer Aadhaar, PAN or bank details here.

| Piece          | Service                     | Free-tier catch                                         |
| -------------- | --------------------------- | ------------------------------------------------------- |
| API + web app  | Render web service (Docker) | Sleeps after ~15 min idle; first request takes ~30-60 s |
| Database       | Neon Postgres               | 0.5 GB; compute pauses when idle, wakes in ~1 s         |
| Uploaded files | Cloudflare R2               | 10 GB free; needs a card on file to enable              |

One container serves both the API (`/api/...`) and the web app, so there is no CORS and the login cookie works as is.
On every start `scripts/start-prod.sh` applies migrations, ensures the roles and Super Admin exist, and (when
`SEED_DEMO=true`) loads the demo data. All of that is idempotent.

## One-time setup

1. **Neon**: create a project, copy the connection string (the direct one, not the pooled `-pooler` one, because
   migrations need a direct connection). It ends in `?sslmode=require`.
2. **Cloudflare R2**: create a bucket (e.g. `jana-docs`), then _Manage R2 API Tokens_ -> create a token with
   Object Read & Write on that bucket. Note the endpoint `https://<account-id>.r2.cloudflarestorage.com`, the access
   key id and the secret. Keep the bucket private.
3. **Render**: New -> Blueprint -> connect the GitHub repo. It reads `render.yaml`. Fill the prompted values:

   | Variable                                                     | Value                                                                  |
   | ------------------------------------------------------------ | ---------------------------------------------------------------------- |
   | `DATABASE_URL`                                               | the Neon string                                                        |
   | `WEB_ORIGIN`                                                 | `https://<service-name>.onrender.com` (used in invite and reset links) |
   | `SEED_SUPERADMIN_EMAIL` / `SEED_SUPERADMIN_PASSWORD`         | your login (password: 12+ chars, upper, lower, digit, symbol)          |
   | `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | from R2                                                                |

   `JWT_ACCESS_SECRET`, `FIELD_ENCRYPTION_KEY` and `BLIND_INDEX_KEY` are generated by Render. **Do not change
   `FIELD_ENCRYPTION_KEY` afterwards**: stored ID and bank numbers become unreadable.

4. Deploy. Open `https://<service-name>.onrender.com`, sign in as the Super Admin. You must change the password and set
   up 2FA on first login. Every push to `main` redeploys automatically.

## Checks after a deploy

- `https://<service-name>.onrender.com/api/health` returns `{"status":"ok"}`.
- Upload a customer photo, restart the service from the Render dashboard, and confirm the photo is still there (proves
  R2 is used, not the container's disk).
- Bulk upload page: download the template and import a row.

## Things to know

- **Cold start**: after idle time the first page load is slow. Keep-alive pingers work around it but are against the
  spirit of the free tier; don't rely on them.
- **Demo logins** (when `SEED_DEMO=true`): `meera@demo.jana` (Manager) and `sathish@demo.jana` (Staff), password
  `Demo!Passw0rd#1`. **Anyone who reads this repo knows that password.** Set `SEED_DEMO=false` once your testers have
  their own accounts, and delete the demo users.
- **Lost Super Admin access**: use Render's Shell tab: `cd apps/api && npx ts-node prisma/reset-superadmin.ts`.
- **Swagger docs** are off in production by design.
- **Other hosts**: the image is host-neutral. Koyeb, Fly.io or any Docker host works with the same variables. Build
  locally with `docker build -t jana-finance .`.
- **Moving to real use later**: a paid always-on host, Neon/managed Postgres with backups, a proper domain, and
  a review of `docs/progress.md` hardening items first.
