# API

Base URL `http://localhost:3000/api` (everything is under the `/api` prefix; the web dev server proxies it, in production the reverse proxy does). JSON. Auth: `Authorization: Bearer <accessToken>` (15 min). The refresh token lives in an httpOnly, SameSite=Strict cookie `jana_rt` scoped to `/auth`. Every endpoint requires authentication unless marked **public**. Errors look like `{ "code": "FORBIDDEN", "message": "..." }`; validation errors return 400 with `code: "VALIDATION_FAILED"`.

List endpoints accept `page`, `pageSize` (max 100), `q` (search) and `sort=field:asc|desc`, and return `{ items, page, pageSize, total }`.

Interactive OpenAPI docs are served at `/api/docs` (JSON at `/api/docs-json`) outside production. They list every route and the auth scheme; request-body schemas are not shown yet because validation uses Zod (`packages/shared/src/schemas.ts` is the source of truth for bodies).

## Auth

| Method      | Path                                   | Notes                                                                                                                                                       |
| ----------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST        | `/auth/login`                          | **public**, 10/min. Body `{ email, password, totp? }`. 401 `TOTP_REQUIRED` when 2FA is on and no code sent. 423 `ACCOUNT_LOCKED` after 5 failures (15 min). |
| POST        | `/auth/refresh`                        | **public**. Rotates the refresh cookie.                                                                                                                     |
| POST        | `/auth/logout`                         | **public**. Revokes the current session.                                                                                                                    |
| POST        | `/auth/accept-token`                   | **public**. Body `{ token, password }`. Used for invites and password resets. Single use.                                                                   |
| GET         | `/auth/me`                             | Current user and permission list.                                                                                                                           |
| POST        | `/auth/change-password`                | Revokes all other sessions.                                                                                                                                 |
| POST        | `/auth/2fa/setup`, `/auth/2fa/enable`  | TOTP. Mandatory for the Super Admin.                                                                                                                        |
| GET, DELETE | `/auth/sessions`, `/auth/sessions/:id` | Active sessions of the current user.                                                                                                                        |

Until the password is changed (and, for the Super Admin, 2FA is enabled) every other endpoint returns 403 `SETUP_REQUIRED`.

Rules enforced server-side: the Super Admin role cannot be assigned, edited or deleted and its user cannot be suspended, edited, reset or deleted by anyone (`PROTECTED`); nobody can assign a role or grant a permission they do not hold (`ESCALATION`); you cannot suspend or delete yourself.

## Customers and KYC

All list endpoints take `page`, `pageSize`, `q`, `sort`. The customer list also takes `status` (default: everything except drafts), `risk`, `category`, `kyc`, `cibilMin`, `cibilMax`, `watch`, `tag`. Searching by a 12-digit Aadhaar or a PAN is an exact match through the blind index; partial numbers never match.

### KYC documents and files

| Method | Path                                     | Permission   | Notes                                                                                                                                                                                          |
| ------ | ---------------------------------------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST   | `/customers/:id/documents/:type/files`   | `kyc:upload` | Multipart `file` + `label`. Max 5 MB. Type is decided from the file's bytes (JPG, PNG, WebP, PDF). PHOTO and SIGNATURE keep one file (replaced on upload). New evidence resets a verification. |
| DELETE | `/customers/:id/documents/files/:fileId` | `kyc:upload` | Blocked while the document is VERIFIED.                                                                                                                                                        |
| POST   | `/customers/:id/documents/:type/verify`  | `kyc:verify` |                                                                                                                                                                                                |
| POST   | `/customers/:id/documents/:type/reject`  | `kyc:reject` | Body `{ reason }`.                                                                                                                                                                             |
| GET    | `/files/:id/url`                         | `kyc:view`   | 60-second signed link; every issue is audited.                                                                                                                                                 |
| GET    | `/files/:id/content?e=&s=`               | signature    | The signature is the credential, so `<img>` works. `Cache-Control: no-store`.                                                                                                                  |

`type` is one of `AADHAAR, PAN, VOTER_ID, DRIVING_LICENCE, PASSPORT, PHOTO, SIGNATURE, ADDRESS_PROOF, INCOME_PROOF, BANK_STATEMENT, OTHER`.

## Chit funds

Amounts are whole paise; rates are basis points (500 = 5%). `Idempotency-Key` is required when taking a payment.

### Bulk customer import (Excel)

Two steps: check the whole file (nothing is saved), then import the checked rows. The uploaded rows are held encrypted for 24 hours. Every endpoint below needs `customer:import`; the ones that check or import also need `customer:create` and `kyc:upload`, since they write customers and KYC numbers.

| Method | Path                                                                 | Notes                                                                                                                                                                                                                                                                                 |
| ------ | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | `/customers/import/template`                                         | The `.xlsx` template: Instructions sheet, Customers sheet (mandatory headers marked `*`, dropdowns, date and number rules, text-formatted ID columns), hidden lists and a version marker.                                                                                             |
| POST   | `/customers/import/validate`                                         | Multipart `file` (`.xlsx` or `.csv`, max 5 MB, max 1,000 rows). Returns a report: counts of ready, errors and possible duplicates, and per row the spreadsheet row number, name, each column error (`header`, `message`) or the matching customers. Never returns ID or bank numbers. |
| GET    | `/customers/import/batches`                                          | Recent uploads with counts and what can still be done. Own uploads only; the Super Admin sees all.                                                                                                                                                                                    |
| GET    | `/customers/import/batches/:id`                                      | Re-opens a held batch with the same report. A fully imported batch returns an empty row list.                                                                                                                                                                                         |
| GET    | `/customers/import/batches/:id/errors?rows=errors` (or `duplicates`) | The "rows to fix" workbook: template layout, only the failed rows, offending cells highlighted, plus `Row in your file` and `Errors` columns (ignored on re-upload).                                                                                                                  |
| POST   | `/customers/import/batches/:id/run`                                  | Body `{ includeDuplicates?: boolean }`. Creates the ready rows (and duplicates only if asked) as complete DRAFT customers. Runs once: a second call is 409.                                                                                                                           |
| DELETE | `/customers/import/batches/:id`                                      | Discards the upload and removes its data.                                                                                                                                                                                                                                             |

Whole-file problems return 400 with a code and a plain message: `UNSUPPORTED_FILE`, `NOT_THE_TEMPLATE`, `MISSING_COLUMNS`, `OLD_TEMPLATE`, `EMPTY_FILE`, `TOO_MANY_ROWS`, `FILE_TOO_LARGE`, `NO_FILE`.
